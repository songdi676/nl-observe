## 1. 需求是什么

**前端透明化建设**：让业务方从浏览器视角看清"业务流程跑了多久、慢在哪、成功率多少"。交付一条自建的前端可观测链路：

```
浏览器 Web SDK（Vue2/Vue3 双框架）
  → receiver（内嵌 OpenTelemetry Collector，OTLP/HTTP 4318，IP 白名单+限流）
  → Kafka（traces/metrics/logs 三 topic）
  → storage（OTLP 解析 → Databend 三表）
  → query（业务列表 / 链路 span 树 / 首屏+业务耗时 P95 与成功率）
  → web-ui（查询界面）
```

核心能力：签入客户（signIn）→ 业务流程状态机（start/resume/挂起/有效耗时）→ REST 请求自动埋点 → 首屏/业务耗时指标 → sendBeacon 卸载冲刷。需求来源：概要设计（2026-09-28）→ 详细设计 → 23 项任务清单（`tasks.md`）。

## 6. 对 nl-sdlc 插件的验证结论

**通过验证，可用于生产特性开发。** 分维度评价：

| 维度 | 评价 |
|---|---|
| 需求→任务分解 | 优。详设 → 23 任务（含验收/测试用例/deps）→ 拓扑 7 层，依赖关系正确，无环 |
| 并行编排 | 良。层内 worktree 并行 + 层间串行合入有效；串扰风险（T23 M-1）被评审发现并制度化（端口三处同读规范） |
| 质量门 | 优。打回机制真实拦截了代码缺陷（Critical/Major 全部在合入前修复）；且能区分环境性失败，未造成无效返工 |
| 三视角评审 | 优。security 视角多次发现真实问题（fail-closed、凭据剥离、CORS 跳板风险）；architecture 视角抓住了并发/状态机类缺陷 |
| 人机协作 | 良。交付合并前人工批准、私服/环境类问题人工介入点清晰；未出现越权自动推送 |
| 成本可控性 | 优。子代理可替换为内网模型，无外部 API 依赖；token 消耗可度量（本次 11.2M/23 任务） |

**待改进（本次暴露）**：
1. 权限判定/分类器（qwen 判定通道）间歇性不可用，尾段（部署收尾）被阻塞 20 分钟级，建议判定通道做降级/多模型兜底
2. dependency-check 在 NVD 不可达时只有"skipped"，缺内网镜像数据源的降级路径
3. 长任务（>6h）无中间进度外显，用户只能凭提交记录判断进展，建议加阶段心跳汇报
4. 一次性初始化类步骤（Databend 建库建表）在插件流程外手工补齐——此类"环境引导"任务可纳入 tasks.md 模板
