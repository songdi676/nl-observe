- 依据：docs/designs/2026-09-28-前端透明化建设-design.md（v3 定稿）、docs/requirements/需求.md
- 需求编号引用：US-01…US-10 / AC-01…AC-10 / NFR-01…NFR-04
- 约定：本文所有 Databend/Kafka 凭证一律环境变量占位（`DATABEND_URL`/`DATABEND_USER`/`DATABEND_PASSWORD`/`KAFKA_BOOTSTRAP_SERVERS`），具体连接串见需求文档，代码与文档不落口令

## 1. 模块实现方案

### 1.1 backend-observe-common（Java 17，被三服务单向依赖）

包结构 `com.nlolobserve.common`：

```
ddl/          TableNames、Columns、DdlScripts（三表 DDL 常量，单一事实来源）
dto/          BusinessItem、SpanNode、SpanTree、SpanDetail、MetricSummary、BizMetric
model/        OtlpTracePayload、OtlpMetricPayload、OtlpLogPayload（OTLP/JSON 反序列化模型）
constant/     AttributeKeys（nl.*、biz.*、http.* 白名单常量）、Topics（三 topic 名）
web/          ApiResult<T>（{code,message,data}）、ErrorCode（见 §4.1）
```

### 1.2 backend-observe-receiver

包结构 `com.nlolobserve.receiver`：

```
config/       KafkaExporterProperties（@ConfigurationProperties 前缀 observe.kafka，字段与需求 yaml 一一对应）、SecurityFilterProperties（observe.security：allowed-cidrs、max-request-bytes=10485760、rate-limit-per-min=600）
collector/    EmbeddedCollectorConfig（Spring Boot 3 生命周期内启动/停止 collector-embedded 1.2.1；OTLP receiver 仅启用 HTTP，端口 observe.otlp.port 默认 4318；Kafka exporter 配置绑定 KafkaExporterProperties）
web/          ProducerConfigController（GET /config/producer，返回生效 producer 参数 Map，只读）
filter/       IpWhitelistFilter（CIDR 匹配，拒绝 403）、MaxRequestBodyFilter（超限 413）、RateLimitFilter（滑动窗口，超限 429）
metrics/      DroppedCounter（micrometer Counter "nl.receiver.dropped"，collector 导出失败回调处计数）
```

- collector-embedded 以库方式嵌入：应用启动时构建 embedded collector（OTLP HTTP receiver → Kafka exporter×3 → 按信号路由三 topic），`SmartLifecycle` 管理启停。POC（T01）先行验证 1.2.1 与 SB3/JDK17 兼容及失败回调钩子；若无丢弃回调钩子，则用 micrometer 包装 Kafka producer send 异常计数。
- 端口可配置：`observe.otlp.port=4318`（集成测试 `@DynamicPropertySource` 随机端口）。

### 1.3 backend-observe-storage

包结构 `com.nlolobserve.storage`：

```
config/   DatabendProperties（observe.databend.url/user/password，url 必须含 presigned_url_disabled=true，启动时 Assert 自检）、KafkaConsumerProperties（组 nl-observe-storage）
consumer/ TracesConsumer、MetricsConsumer、LogsConsumer（三独立 listener；手动/同步提交 offset：写库成功后 commit → at-least-once）
parse/    OtlpJsonParser（OTLP/JSON → 行模型；trace 展开 resource/scope/attributes JSON 串、提取 nl.customer_id/biz_code/effective_duration_ms；metric 展开 data point 并计算 dp_hash；log 计算 row_hash）
repo/     SpansRepository、MetricsRepository、LogsRepository（JdbcTemplate batch insert；命名参数，禁止拼接）
```

- 批量策略：listener 批处理（`batch.listener=true`），单批 500 行 JDBC batch；写失败重试 3 次后记录 error 日志并跳过该批（offset 不提交，依赖重投 + Replacing 去重兜底重复）。
- 启动自检：`ApplicationRunner` 执行 `SELECT 1`，失败即启动失败（快速暴露 presigned_url/网络问题）。

### 1.4 backend-observe-query

包结构 `com.nlolobserve.query`：

```
config/   DatabendProperties（只读账号；同 presigned_url_disabled 自检）
web/      BusinessesController、TracesController、MetricsController、AuditLogFilter（拦截 /api/observe/**，记录 method/path/customerId/traceId 到独立 audit log 文件）
service/  BusinessQueryService、SpanTreeService、MetricSummaryService
repo/     QueryRepository（JdbcTemplate 命名参数；span 树查询 `... FINAL`）
```

- 鉴权：web-ui 与 API 同经业务系统既有网关（外部边界依赖）；本服务不内置鉴权逻辑，仅审计（落地方式待澄清 #6，预留 SecurityConfig 空壳注释说明）。
- 参数校验：from/to 必填（`yyyy-MM-dd`，跨度 ≤ 31 天，超限 400）；`/metrics/summary` 不带 customerId 时走限流桶（60 次/分）。

### 1.5 sdk-web（npm 包 `@nl-observe/sdk-web`）

```
src/
  core/
    client.ts        NlObserveClient 门面（init/sign_in/sign_out/startBusiness/suspendBusiness/resumeBusiness/endBusiness/trackRest）
    SigninManager.ts 签入状态机（状态：SIGNED_OUT/SIGNED_IN；sign_in 互斥：已签入则先 sign_out 再签入，console.warn）
    BusinessManager.ts 业务实例表 Map<bizId, BizInstance>（状态 ACTIVE/SUSPENDED/ENDED）
      startBusiness: 将其他 ACTIVE 置 SUSPENDED（记 span event biz.suspend_start + 挂起起点时间戳）
      resume: 记 biz.resume event，累计挂起时长
      end: 写 attributes biz.total_suspended_ms / biz.effective_duration_ms（= wallClock - Σsuspended）/ biz.status / biz.end_reason；end span；发 nl.business_duration data point
    rest/autoprofile.ts 包装 fetch 与 XMLHttpRequest（send/open 钩子），生成 REST span（parent=当前 ACTIVE 业务 root span；无 ACTIVE 则不上报），属性仅白名单；路由规范化 http.route（去 query）
    perf/metrics.ts nl.first_screen_load（PerformanceObserver LCP 兜底 load 事件，每页一次）、nl.sdk.flush（flush 结果）
    flush.ts         pagehide + visibilitychange=hidden → forceFlush()（OTLP/HTTP sendBeacon 模式）；失败/超时上报 nl.sdk.flush{result:fail|timeout, dropped_spans}
    guard.ts         单例守卫：window.__NL_OBSERVE__（{version, instance}），重复 init 返回既有实例并 warn
  adapters/
    vue2/index.ts    Vue.directive('biz'/'span') 注册；指令钩子 bound/unbound
    vue3/index.ts    app.directive 注册；created/unmounted
  index.ts           默认导出（框架无关 core）
  vue2.ts / vue3.ts  双入口构建（tsup/rollup：es + cjs 双格式，vue2 入口声明 peerDep vue@^2、vue3 入口 vue@^3）
```

- OTel 集成：基于 `@opentelemetry/sdk-web` + `@opentelemetry/exporter-trace-otlp-http` / `exporter-metrics-otlp-http`（版本 POC 验证）；`WebTracerProvider`，业务 root span 以 `startSpan(name, {links:[], attributes})` 且不带 active context 作为 root（或显式 `ROOT_CONTEXT`）保证不同 traceId；`batchTimeout` 默认 2000ms 可配。
- 挂起语义：span 不结束（保留 OTel 墙钟时长原义），挂起/恢复仅 span event + 属性。
- 测试宿主：`sdk-web/test/vue2-host`、`sdk-web/test/vue3-host`（Vitest + jsdom + @vue/test-utils v1/v2 各一）。

### 1.6 web-ui（Vue3 + Vite + TS）

```
src/
  api/      observeApi.ts（axios 封装 /api/observe/*，统一解包 {code,message,data}）
  pages/    BusinessesPage（客户业务列表：客户编号输入 + 时间范围 + bizCode 过滤）
            TracePage（业务流程时间线：span 树渲染为瀑布/时间线，REST span 高亮展开白名单属性；点击 span 看详情）
            MetricsPage（指标卡片：firstScreenLoadP95、perBiz effectiveDurationP95 / successRate / count）
  components/ SpanTimeline.vue、SpanDetailDrawer.vue、MetricCard.vue
```

- 鉴权：与业务系统既有网关同会话（路由守卫跳转登录为外部依赖，代码只处理 401 → 跳转）。
- 查询恒带 customerId（跨客户运维视图暂不建 UI，仅 API 能力）。

## 2. 接口定义（请求/响应）

### 2.1 GET /api/observe/customers/{customerId}/businesses

Query：`from=2026-09-01&to=2026-09-28&bizCode=ORDER`（from/to 必填，bizCode 可选）

```json
{ "code": 0, "message": "ok",
  "data": [ { "bizId": "b-001", "bizCode": "ORDER", "traceId": "4bf92f35…",
              "startTime": "2026-09-28T09:00:00.000Z", "effectiveDurationMs": 45210,
              "status": "success", "endReason": "explicit" } ] }
```

SQL 形态（命名参数）：`SELECT ... FROM otel_spans FINAL WHERE customer_id=:cid AND name='biz.business' OR ...`（实现取业务 root span：`name LIKE 'biz.business.%'`，按 start_time 倒序，LIMIT 200 上限）。

### 2.2 GET /api/observe/customers/{customerId}/traces/{traceId}

```json
{ "code": 0, "message": "ok",
  "data": { "traceId": "4bf92f35…",
    "spans": [ { "spanId": "s1", "parentSpanId": "", "name": "biz.business.ORDER",
                 "kind": 1, "startTime": "…", "endTime": "…", "statusCode": 0,
                 "durationMs": 45210, "effectiveDurationMs": 45210,
                 "attributes": { "biz.status": "success" }, "events": [ {"name":"biz.suspend_start"} ] } ] } }
```

（`SELECT * FROM otel_spans FINAL WHERE customer_id=:cid AND trace_id=:tid ORDER BY start_time`）

### 2.3 GET /api/observe/customers/{customerId}/traces/{traceId}/spans/{spanId}

返回单 span 全字段（attributes_json/scope_json/resource_json 解析为对象）。

### 2.4 GET /api/observe/metrics/summary

Query：`from&to` 必填、`bizCode` 可选、`customerId` 可选（缺省=跨客户运维视图，限流桶）。

```json
{ "code": 0, "message": "ok",
  "data": { "firstScreenLoadP95": 1830.5,
            "perBiz": [ { "bizCode": "ORDER", "effectiveDurationP95": 52100.0,
                           "successRate": 0.982, "count": 552 } ] } }
```

SQL 形态：P95 用 Databend `quantile(0.95)(value)`；成功率 `sum(biz_status='success') / count(*)`（attributes 提取或落库前抽列，实现时以 `jsonExtractString(attributes_json,'$.biz.status')`）。

### 2.5 GET /api/observe-receiver/config/producer

```json
{ "code": 0, "message": "ok",
  "data": { "bootstrapServers": "10.1.8.33:9092", "acks": "all", "idempotence": true,
            "compressionType": "lz4", "lingerMs": 5, "batchSize": 65536,
            "deliveryTimeoutMs": 20000, "requestTimeoutMs": 15000, "retries": 2147483647,
            "maxInFlight": 5, "maxBlockMs": 5000, "bufferMemory": 67108864, "sendTimeoutMs": 9000 } }
```

## 4. 异常处理约定

### 4.1 统一响应与错误码

| code | 含义 | HTTP |
|---|---|---|
| 0 | 成功 | 200 |
| 40001 | 参数缺失/格式错误（from/to 必填、日期跨度>31天） | 400 |
| 40301 | IP 白名单拒绝（接收端） | 403 |
| 40401 | trace/span/客户无数据 | 404 |
| 41301 | 请求体超限（接收端） | 413 |
| 42901 | 限流（接收端/运维视图） | 429 |
| 50000 | 服务端内部错误 | 500 |

### 4.2 各环节异常策略

| 环节 | 异常 | 策略 |
|---|---|---|
| SDK init 失败/endpoint 不可达 | 上报失败 | 静默降级：console.debug + 不抛错阻断业务；span 仍本地生成（InMemory 丢弃），不影响业务办理 |
| SDK flush | sendBeacon 失败/超时 | 尽力上报 nl.sdk.flush（result=fail/timeout, dropped_spans）；再次失败仅 console |
| 接收端 → Kafka | 发送失败（超时/acks） | 快速失败（max-block 5s）→ 丢弃计数 nl.receiver.dropped；OTLP 入口对客户端返回 200（避免浏览器端无限重试风暴），丢弃有计数可观测 |
| 接收端 | 非法/超大/超频请求 | 403/413/429 直接拒绝 |
| 存储端 | 写库失败 | 批内重试 3 次 → error 日志 + 跳过该批（offset 不提交，重投兜底；Replacing 去重防重） |
| 存储端 | 启动连接自检失败 | 启动失败（fail-fast） |
| 查询端 | 查询超时/无数据 | 50000 / 40401；查询超时 10s（`setLockTimeout`/语句超时） |
| web-ui | API 401 | 跳转登录（外部网关）；5xx 展示重试 |

### 4.3 重试/幂等总原则

- 全链路 at-least-once + 幂等去重（Replacing+FINAL），不做 exactly-once
- 查询端只读无副作用
- SDK 端无重试队列（浏览器端丢弃容忍，计数上报）

## 6. 测试策略

### 6.1 单元（TDD，先测后码）

| 对象 | 关键断言 |
|---|---|
| SigninManager | 重复 sign_in 触发隐式 sign_out；sign_out 后 startBusiness 拒绝（warn+no-op） |
| BusinessManager | startBusiness(B) 后 A 状态 SUSPENDED 且 A root span 未 end；A、B traceId 不同；resume+end 后 effective_duration_ms = 墙钟 - Σ挂起（确定性值，InMemorySpanExporter 断言 span event 与属性） |
| rest/autoprofile | fetch 成功/失败均产生 REST span，parent=ACTIVE 业务 root span；无 ACTIVE 业务不上报；属性仅白名单 4 项；route 去 query |
| perf/metrics | first_screen_load 每页仅一个 data point；business_duration 每业务一个且 attributes 含 biz_status/end_reason |
| flush | visibilitychange=hidden 触发 flush；forceFlush 失败上报 nl.sdk.flush{result:'fail', dropped_spans:N} |
| guard | 二次 init 返回同一实例 |
| OtlpJsonParser | 给定样例 ExportTraceServiceRequest JSON → 行模型字段正确、dp_hash/row_hash 稳定 |
| SpansRepository | 命名参数拼装（mock JDBC 断言无拼接） |

### 6.2 集成

- receiver：Testcontainers Kafka（3 topic 预建）+ 进程内真实 OTLP 端点（随机端口）→ 发样例 OTLP/HTTP → 断言三 topic 消息体与 key=customer_id；`/config/producer` 返回参数与需求 yaml 一致；停 Kafka 容器 → 断言 200 + `nl.receiver.dropped` 递增；非白名单 IP/超大 body/超频 → 403/413/429
- storage：Testcontainers Databend（镜像 databend-query，若内网不可得则降级 JDBC repository mock，env-gated）→ 灌样例 → 断言三表行数/字段；同一 span 灌两次 → `FINAL` 查询 1 行
- query：内嵌 H2 不适用（Databend SQL 方言）→ 依赖 Testcontainers Databend（env-gated）或 repository mock；Newman 对真实环境

### 6.3 API（tests/api/，Newman）

- 集合 `observe-query.collection.json`：businesses/trace/span/metrics-summary 正常 + 参数错误（缺 from/to、跨度>31天）+ 404 用例；`observe-receiver.collection.json`：/config/producer 参数断言
- 环境变量：`BASE_URL_QUERY`、`TEST_CUSTOMER_ID` 等

### 6.4 E2E（tests/e2e/，Playwright，env-gated）

- `full-chain.spec.ts`：测试宿主页（vue3-host 起 vite dev）→ 页面操作：签入客户 → 业务 A（发起真实 fetch 到 mock 后端）→ 切业务 B（A 挂起）→ 恢复 A 结束 A → 结束 B → 断言：查询 API 返回 2 个业务且 traceId 不同、A 的 REST span 归属正确、effectiveDurationMs 合理区间（宽松）
- `metrics.spec.ts`：first_screen_load 数据点存在性（不断言精确值）
- 内网 Kafka/Databend 可达时跑全链路；不可达时跳过（env-gate 条件：`E2E_BACKEND_URL` 未设置则 skip）

### 6.5 POC 验收断言（T01/T21）

- T01：collector-embedded 1.2.1 在 SB3/JDK17 启动 HTTP 4318 并成功写 Testcontainers Kafka；@opentelemetry/sdk-web 最新版在 vue2/vue3 宿主可初始化
- T21：micro-app jsSandbox 开启的子应用 fetch 被自动埋点捕获（捕获率断言：10 次请求 ≥9 次产生 span）；不达标则记录并启用 trackRest 兜底路径
