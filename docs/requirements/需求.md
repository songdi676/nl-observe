# 前端透明化建设
使用原生 OpenTelemetry API 打造前端透明化平台。供电信运营商业务办理系统接入使用。
实现 业务办理流程可视。
电信运营商业务办理系统分为基座应用（有多个模块，使用MF模块联邦构建，版本为vue2）和子应用:统一货架、订单、产商品配置、已订购、购物车等（micro-app接入,版本为vue3）
### 前端sdk
基于OpenTelemetry进行薄封装，提供自己统一的web接入sdk
- vue2、vue3双版本兼容
- 提供vue指令管理context、span.简化业务接入使用复杂度
- 一次只可以签入一个客户，可以办理多个业务，如办理A、B两个业务，办理B的时候，A处于挂起状态。A、B有不同的trace id。可以看到2个业务的办理流程，包括后台rest接口调用情况。
- 支持采集一些性能指标，如首屏加载。每个业务的耗时、成功率
### 后端接收端 
基于spring boot3开发，嵌入 
```xml
<dependency>
    <groupId>io.mishmash.opentelemetry</groupId>
    <artifactId>collector-embedded</artifactId>
    <version>1.2.1</version>
    <scope>compile</scope>
</dependency>
```
把接收到的指写入kafka信息：
```yaml
traces-topic: nl-observe.otlp.traces
    metrics-topic: nl-observe.otlp.metrics
    logs-topic: nl-observe.otlp.logs
    kafka:
      bootstrap-servers: 10.1.8.33:9092
      acks: all
      idempotence: true
      compression-type: lz4
      linger-ms: 5
      batch-size: 65536
      # delivery.timeout.ms 必须 >= linger.ms + request.timeout.ms
      delivery-timeout-ms: 20000
      request-timeout-ms: 15000
      retries: 2147483647
      max-in-flight: 5
      # Kafka 不可达时快速失败(毫秒)
      max-block-ms: 5000
      buffer-memory: 67108864
      # 单条消息等待确认上限(毫秒), 需小于库的批次超时(10s)
      send-timeout-ms: 9000
```
### 后端存储端 
基于spring boot3开发，消费kafka中的数据，存储到数据库：
    databend:
      # presigned_url_disabled=true: 服务端以本地盘/内置 MinIO 存储时, 驱动不能走
      # 预签名上传 (其地址 127.0.0.1:9000 在服务端外不可达, 会 "Failed to upload stream")
      url: "jdbc:databend://10.1.8.8:8000/default?sslmode=disable&presigned_url_disabled=true"
      username: databend
      password: databend
